## High-value discriminator for scratch cases

The local GCC 4.4.1 `recog.c` copy at `build/compiler-research/gcc441-recog.c:2930–3026` implements `peep2_find_free_register` with a function-static `search_ofs`. Each successful choice advances it; a failure resets it to zero. The choice also rejects hard registers that are live across the pattern, fixed/global, outside the constraint class, unsuitable for the mode, or would require an extra save/restore. `peephole2_optimize` initializes a basic-block ring and liveness sets but does not reset that static cursor. This source copy is a diagnostic reference; its exact provenance against the locked TDM-2 binary is not independently proven here.

For the next *source-backed* `add_floor` probe, retain both full-TU receipts and byte-neutral `181r.csa`/`182r.peephole2` dumps. Compare (1) effective code and all exact peers, (2) emission-order scratch choices before `add_floor`, (3) the `floor_shrink` compare and branch at CSA, and (4) the selected register and surrounding liveness at peephole2. If the prior scratch sequence changes, test a cursor-context explanation. If it is unchanged but local CFG/liveness changes, test the local eligibility explanation. The present baseline/inversion pair has unchanged recorded predecessor choices and different branch edges, so local eligibility is the narrower inference; a precise choice still needs a diagnostic trace of `search_ofs`, `live_before`, rejected registers, and selected pattern inside a separately built diagnostic compiler. The existing dump alone does not expose those internal values.

Stop after that discrimination unless new historical declaration/source evidence appears. Do not infer a historical GCC flag, change production bodies to force a register, or treat masked equality as a function match.
